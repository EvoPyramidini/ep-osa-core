# Правила Среды Пирамиды (The Pyramid Environment Rules)

Поскольку `ep-osa-core` стал чистым абстрактным хабом, а исполняемый код генерируется и поставляется извне (LLM, внешние провайдеры, MCP), **3D-Доска (Пирамида)** перестает быть просто интерфейсом. Она становится **Физикой Исполнения**.

Внешний код, попадая в систему, обязан подчиняться физическим и семантическим правилам этой среды.

---

## Правило 1: Пространственная легитимность (Spatial Manifestation)

**Код не может существовать вне пространства Пирамиды.**

Любой внешний навык, агент или скрипт перед выполнением должен быть "спроецирован" на конкретный узел (`EvoNode`) на определенном Z-уровне Пирамиды.

- Если агента (Puck) нет на доске визуально — он не имеет права на вычисление.
- Интерфейс = Движок. Отрисовка предшествует исполнению.

## Правило 2: Гравитационная маршрутизация (Field-Driven Routing)

**Агенты не вызывают друг друга напрямую. Они следуют за гравитацией.**

Внешний код не может использовать прямые вызовы (например, `agent_A.call(agent_B)`). Вместо этого агент меняет конфигурацию поля:

1. Агент завершает работу и публикует результат.
2. Внешний источник генерирует "магнитный заряд" (от 0.0 до 1.0) для следующего логического узла.
3. Пирамида (Доска-коннектор) считывает этот заряд и физически перемещает агента к новому узлу. Точка прибытия означает старт следующей функции.

## Правило 3: Энергетическая топология Z-уровней (Z-Layer Dimensionality)

**Положение по оси Z определяет права и возможности внешнего кода.**

Пирамида диктует контекст:

- **Верхние уровни (Z17-Z14)**: Стратегия, общение с пользователем, высокий контекст, низкая скорость.
- **Средние уровни (Z13-Z8)**: Оркестрация, сборка навыков, тактика.
- **Нижние уровни (Z7-Z1)**: Быстрые скрипты, файловые операции, база данных.

Внешний код обязан декларировать, для какого Z-уровня он предназначен, иначе Пирамида его отвергнет.

## Правило 4: Абсолютная абстракция Контрактов (JSON Supreme)

**Пирамида не понимает языков программирования. Пирамида понимает только схемы.**

Так как `ep-osa-core` лишен рантайма, внешний код общается с Пирамидой исключительно через JSON-схемы, лежащие в `contracts/`.

- Внешний источник должен прислать объект, строго соответствующий `environment_state.json`.
- Пирамида не знает, что такое Python или TypeScript. Она берет JSON с гравитацией узлов и распределяет свет и движение по 3D-доске.

## Правило 5: Динамическая кристаллизация (Dynamic Instantiation)

**Навыки существуют только тогда, когда они нужны.**

Когда гравитация узла достигает порога активации (например, `> 0.8`), Пирамида "кристаллизует" узел:
Она делает запрос ко внешнему источнику (например, LLM: "Напиши код, чтобы закрыть потребность этого узла"). Код генерируется, исполняется в изолированном внешнем контейнере, результат возвращается в Пирамиду, и узел "гаснется" (магнетизм падает до 0).

---

## Резюме

Пирамида — это не отражение бэкенда. **Пирамида и есть бэкенд.** Она диктует геометрию, по которой вынужден течь внешний код.

---

## Правило 6: Региональный Якорь Среды (Server Environment Anchor)

**Пирамида исполняется в конкретном географическом регионе. Регион — это свойство среды, а не конфигурация инфраструктуры.**

Текущий регион: **`us-west (America)`**

Регион определяет:

- **Маршрутизацию API**: все вызовы Z15-сервисов (Google AI Studio, Gemini, Firebase) направляются через US-инфраструктуру (us-central1 / us-west).
- **Задержку и квоты**: регион выбран для минимизации задержки к Google Cloud US endpoints — критически важным для реактивного агентного оркестрирования.
- **Идентификацию среды**: в статус-баннере и terminal Пирамиды всегда отображается активный регион для мгновенной диагностики.

> Изменение региона — это архитектурная директива AlexCreator. Она фиксируется в terminal (с меткой времени) и транслируется всем узлам Z15 при следующей кристаллизации.

| Параметр         | Значение                    |
|------------------|-----------------------------|
| Регион           | `us-west (America)`         |
| API endpoint     | `us-central1.googleapis.com`|
| Предыдущий       | `auto / EU`                 |
| Статус           | `ACTIVE`                    |
