# 🧠 EP-OSA Container Memory (ep-osa-memory)

## Концепция

Этот скилл реализует механизм **Контейнерной Памяти**, извлеченный из наследия `EvoPyramid 24`. Вместо плоских таблиц или векторных БД, память здесь организована в виде эфемерных и постоянных семантических контейнеров.

## Основные особенности

1. **Контейнеры (Containers)**: Каждый блок памяти (мысль, лог, сессия) инкапсулируется в контейнер с метаданными и идентификатором.
2. **Эфемерность (Auto-delete)**: Контейнеры могут иметь `auto_delete_threshold`, по истечении которого (без доступа) они удаляются. Это позволяет системе "забывать" нерелевантный мусор.
3. **Квантовый скачок (Quantum Leap)**: Уникальный механизм машинного вдохновения. При включенном `quantum_leap` система намеренно извлекает псевдо-случайные, слабо связанные контейнеры памяти, чтобы сгенерировать альтернативный, нестандартный контекст для LLM. Это разрушает зацикливание и стимулирует креативность.

## Интеграция с PEAR Broadcast

Память может быть получателем сообщений типа `broadcast`. Например, при получении системного `reload` или `context_switch`, память может архивировать текущие эфемерные контейнеры.

## Соответствие Конституции

Данный скилл полностью соответствует 10 конституционным принципам, в частности:

- **Принцип 4 (Memory Proportions)**: Система четко разделяет Local (session) и Board (global) память. Эфемерные контейнеры живут в Local, постоянные мигрируют на Board.
- **Принцип 3 (Strict Schema Contracts)**: Взаимодействие идет строго через описанный YAML контракт.
